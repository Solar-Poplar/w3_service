# IEC 62443-3-2

一般而言，大家談到 **IEC 62443** 時，常常會直接提到 **3-2** 或 **3-3**，但這兩份標準的定位其實完全不同。

- **IEC 62443-3-2**
  著重於工業控制系統（IACS）的風險評估、安全需求分析，以及 Zone & Conduit 的設計方法。

- **IEC 62443-3-3**
  定義系統應滿足的技術性安全需求(Security Requirements)，並依 Security Level（SL1～SL4）規範需要達成哪些控制措施。

---

## 1. 3-2 的目的是什麼？

IEC 62443-3-2 的主要目的，是協助企業建立一套系統化的方法，分析工業控制系統的資安風險，並依據風險結果決定系統需要達到的 Security Level。

它回答的是：

> **我的系統需要保護到什麼程度？**

主要工作包含：

- 資產盤點
- Zone & Conduit
- 威脅分析
- 風險評估
- Target Security Level (SL-T)

## 2. 3-2 主要是在做風險評估嗎？

是。

但它並不是一般 IT 常見的 ISO 27005 式風險評估，而是針對工業控制系統(IACS)設計的方法。

特色包括：

- 強調 Zone & Conduit
- 強調設備之間的信任邊界
- 分析完成後決定 Target SL
- 後續交由 3-3 決定需符合哪些 Security Requirement

## 3. 一定要做 Zone & Conduit 嗎？

幾乎可以說是 IEC 62443 最核心的概念。

Zone 用來將具有相同安全需求的設備分群。

Conduit 則定義不同 Zone 之間允許如何通訊。

# IEC 62443-3-3

## 1. 3-3 的目的是什麼？

IEC 62443-3-3 定義的是工業控制系統需要符合哪些資安需求(Security Requirements)。

它回答的是：

> **系統需要做到哪些安全功能？**

## 2. 3-3 有哪些要求？

共分成七大 Foundational Requirements（FR）：

- FR1 Identification and Authentication Control
- FR2 Use Control
- FR3 System Integrity
- FR4 Data Confidentiality
- FR5 Restricted Data Flow
- FR6 Timely Response to Events
- FR7 Resource Availability

每一項再細分成多個 Security Requirement（SR）。

## 3. Security Level 是什麼？

IEC 62443 定義四個 Security Level：

- SL1：抵抗偶然或非刻意攻擊
- SL2：抵抗具有一般能力的攻擊者
- SL3：抵抗具有專業能力且有組織的攻擊者
- SL4：抵抗高度資源且技術成熟的攻擊者

## 4. 3-2 與 3-3 有什麼關係？

導入流程如下：

```text
系統盤點
      │
      ▼
Zone & Conduit
      │
      ▼
IEC 62443-3-2
風險評估
      │
      ▼
決定 Target SL
      │
      ▼
IEC 62443-3-3
選擇需要符合的 SR
      │
      ▼
實作安全控制
```

可以簡單理解為：

- **3-2：決定需要多少安全。**
- **3-3：定義如何達到這個安全。**
