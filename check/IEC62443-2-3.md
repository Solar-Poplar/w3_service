# IEC 62443-2-3：Patch Management in the IACS Environment

> **定位：** IEC 62443-2-3 提供工業自動化與控制系統（IACS）環境中的修補程式（Patch）管理要求與最佳實務，協助企業在兼顧可用性與安全性的前提下，建立可持續運作的 Patch Management Process。

# 什麼是 IEC 62443-2-3？

IEC 62443-2-3 聚焦於工業控制系統的修補程式管理流程。

其目的並非要求「所有 Patch 都必須立即安裝」，而是要求企業建立一套可評估、可追蹤、可驗證的 Patch Management 機制。

核心目標包括：

- 降低已知弱點造成的風險
- 維持系統可用性
- 控制變更風險
- 建立修補紀錄與追蹤機制

---

# 為什麼 OT 與 IT 不同？

IT 環境通常可快速部署修補程式，但 OT 環境往往需要考量：

- 生產不中斷
- 即時控制需求
- 設備相容性
- 廠商認證
- 停機成本
- 長生命週期設備

因此，OT 更重視「風險評估後再修補」，而非立即更新。

# Patch Management 流程

1. 接收 Patch 或弱點資訊
2. 確認受影響資產
3. 評估風險與影響
4. 測試修補程式
5. 安排停機窗口
6. 正式部署
7. 驗證結果
8. 更新紀錄與持續監控

## Asset Owner

- 決定是否部署 Patch
- 核准停機時程
- 接受剩餘風險

## OEM

- 提供 Patch

- 提供相容性資訊

## SI / 維護商

- 協助測試
- 執行部署
- 驗證功能正常

# 常見誤解

## Q：所有 Patch 都要立即安裝嗎？

不用。IEC 62443 強調應先完成風險評估，再決定是否部署。

## Q：沒有安裝 Patch 就一定不符合 IEC 62443？

不一定。如果經風險評估後採取其他補償控制（Compensating Controls），仍可能符合管理要求。

## Q：OT 是否可以完全禁止更新？

不建議。長期不更新可能導致弱點累積，應建立定期評估與管理機制。

# 總結

IEC 62443-2-3 的重點並非「快速更新」，而是建立一套可管理、可追蹤且兼顧生產可用性的 Patch Management 流程。透過風險評估、測試、部署、驗證與持續追蹤，企業可以有效降低弱點風險，同時維持工業控制系統的穩定運作。
